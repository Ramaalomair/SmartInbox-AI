# Customer Record Access and Identity (POL-SEC-02)
Before disclosing order, invoice, refund, or ticket details, the application must check the requester against `customer_email` (orders/tickets) or `authorized_contacts` (invoices). Access verification is enforced in code at the tool boundary, never solely by LLM instructions. If a record is not associated with the sender, do not reveal whether it exists or provide its details: ask the user to authenticate through an approved channel. A stated record ID does not confer authorization. An email From header alone is not trustworthy authentication in production; these are synthetic test identities for this local prototype. Do not reveal other customer records, OTPs, credentials, or internal directories. The agent must not send emails or export data. Outbound drafts require explicit human approval before persistence.
